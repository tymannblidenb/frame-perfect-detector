# Frame Perfect Detector (Geode)

Считает frame perfect по **физическим шагам** игры, а не по времени/FPS монитора.

## Как это работает
1. Хук `GJBaseGameLayer::processCommands` -> счётчик шагов (один вызов = один шаг).
2. Хук `GJBaseGameLayer::handleButton` -> нажатие/отпускание привязано к точному номеру шага.
3. «Кадр» из настроек переводится в шаги: `window = round(TPS / FPS)`
   (240 TPS и 240 FPS -> 1 шаг; 60 FPS -> 4 шага).
4. FP = интервал между соседними входами (press->release или release->press) <= window.
   Каждый интервал считается один раз.
5. TPS берётся из реального шага игры с учётом timewarp, либо из настройки `tps-override`.

## Чем это лучше версии «1/FPS секунд»
- Окно считается в шагах физики, а не в секундах -> не зависит от FPS монитора и железа.
- Учтены TPS bypass и timewarp.
- Нет двойного счёта, учитываются оба игрока (2-player режим).

## Сборка
```
geode build
```
Нужен Geode SDK (`GEODE_SDK`) и Geode CLI.

## Проверь при первой сборке
- Сигнатуры `processCommands(float)` и `handleButton(bool,int,bool)` в твоей версии bindings.
- Поле `m_gameState.m_timeWarp`.
- Если TPS в HUD «плывёт», задай `tps-override`.

## Ограничения
Это детектор FP по **интервалам между входами**. FP по запасу до хитбоксов (когда клик
нужно сделать ровно в один шаг относительно объекта) требует отдельной логики по уровню.
